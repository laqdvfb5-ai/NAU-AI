## Model-only chat and truthful progress — 2026-09-07

User explicitly changed the requirement: every chat answer must be generated by an AI model, with visible reasoning/searching/answer progress. This supersedes the direct social/evidence fallback behavior described above. `socialIntent` now only classifies intent; it contains no response templates. Chat prepares server-selected `{kind,facts}` for social/public/private/source gaps/hypothetical/insufficient/login-required/access-denied/unsupported-action cases and always calls the configured model once. Only model text becomes an assistant message. `EvidenceProvider` is now an unconfigured sentinel that throws; model errors, empty responses, cancellation and rejected PI wording cannot return or persist a canned/evidence answer. Existing academic evaluation and ownership checks still run on the server. Model prompts support natural general conversation while restricting NAU/private factual claims to current evidence.

SSE status events carry stages from real operations: reasoning (request context), searching (knowledge retrieval), checking (private records), generating (model request), validating (PI wording when relevant). The shared website/embed component shows an accessible animated timeline, elapsed time, streaming, stop and retry. It does not display internal chain-of-thought or advance stages using timers. Request generations isolate late responses after reset/navigation/logout. Initial hydration gating fixes a race where SSR-disabled textareas could remain disabled after the provider had already loaded. SSE uses Cache-Control no-transform so Next's gzip layer cannot buffer progress until the response ends; the same fix applies to pool test streaming.
